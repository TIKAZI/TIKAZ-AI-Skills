# 网页验收与部署

## 自动检查

先发现项目已有命令，再运行适用项：lint、typecheck、unit tests、integration/e2e tests、production build。不要用通用命令覆盖仓库约定。运行 `python '<skill-root>/scripts/audit_frontend.py' '<project-path>'` 作为补充警报，不把它当浏览器验收替代品；处理每条 finding 并记录修复或项目级豁免。需要让所有 warning 阻断 CI 时显式加 `--strict`，不要默认把上下文型 anti-slop 警告升级为错误。

## 渲染检查

至少检查：

- 1920 或目标宽屏：主次结构清楚，不因过宽而失去阅读宽度。
- 1366 或目标窗口：无横向滚动、遮挡、按钮粘连、标题短尾或异常竖排。
- 390 左右移动宽度：导航、触控目标、文本、媒体、表格和固定元素可用。

在真实浏览器读取页面状态、控制台和网络错误。截图覆盖完整页面和关键局部；同一轮批量看，避免逐像素来回修改。

## 状态与交互

逐条走真实用户路径，并验证：默认、hover、focus-visible、pressed、disabled、loading、empty、success、error、validation、offline 或权限不足（适用时）。确认返回路径、深链路和 404。键盘和触控必须能完成核心任务。

## 性能和动效

- 检查首屏字体、图片和脚本成本，避免只为装饰加载重型库。
- 检查布局偏移、水平溢出、主线程长任务和持续 GPU 动画。
- 切换 reduced motion，确认内容仍可见、状态仍清楚、滚动未锁死。
- 重复触发、快速中断、路由前进后退，确认监听器、ScrollTrigger 或动画实例已清理。

## 修复循环

1. 汇总截图、控制台、自动检查和交互路径的证据。
2. 先修 token、布局合同、组件状态等系统性根因。
3. 一次集中修改同类问题。
4. 重新运行受影响测试和构建。
5. 对相同视口和路径复核一次；只有新证据显示缺陷时继续。

## 部署路径

| 路径 | 适用 | 验证 |
|---|---|---|
| 本地预览 | 设计评审、开发中交付 | 启动命令、端口、浏览器状态 |
| 静态托管 | 无服务端状态的站点 | 构建目录、SPA 回退、资源路径 |
| 托管平台 | 框架集成、预览环境 | 环境变量、构建日志、预览/生产 URL |
| 自托管/服务器 | 特定网络、数据或运维要求 | 进程、反代、TLS、持久化、回滚 |

若项目已有部署配置，优先沿用。若没有，先给出 2–4 个真正影响维护、成本或权限的选项并明确推荐。外部发布前必须先通过本地生产构建。发布后再次检查 URL、主要路由、静态资源、控制台和移动视口。

## 交付证据

最终说明：设计方向和动效主张、文件变化、来源与许可判断、运行过的命令、通过/失败结果、检查过的视口和路径、截图位置、访问 URL 或启动命令、未解决限制。生产部署还要记录非敏感的提交或构建 ID、平台项目和环境、部署时间、前一稳定版本、回滚命令及一次回滚可用性检查。不要仅说“已完成”。
