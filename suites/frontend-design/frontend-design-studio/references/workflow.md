# 工作流路由

## 新建界面

1. 收集产品事实：用户、核心任务、内容、业务约束、目标设备、已有品牌资产。
2. 判定界面类型：说服型、操作型、阅读型或体验型。
3. 写出 Design Read，设置 variance/motion/density，并定义主构图、signature moment、资产语言和三项 anti-goals。
4. 研究两到三个互补来源，记录可借鉴的结构或机制及不可复制项。
5. 创建 `DESIGN.md`，锁定唯一视觉世界、区块构图图谱、tokens、状态、资产和动效预算。
6. 先实现导航/应用框架、第一视口和一个代表区块作为艺术指导样片；桌面/移动截图通过后再扩展整页。
7. 完成静态层级和响应式骨架，再做关键交互、动效和表面质感。
8. 分开运行视觉评审与实现审计，集中修复，再复核一次。

## 改造既有界面

1. 读取现有页面、路由、组件、样式、测试和截图，不从零重写。
2. 先判断执行 `bolder`、`distill`、`polish` 还是完整 redesign，再按影响排序诊断：信息架构、内容层级、主构图、资产、字体与颜色、布局与响应式、组件表达、状态、动效、细节。
3. 识别系统性原因，例如 token 缺失、断点漂移、组件状态不完整；不要只在 CSS 末尾加补丁。
4. 先完成第一视口和一个代表状态的同视口样片，保持功能和数据契约不变；样片成立后再批量推广规则。
5. 对修改前后使用同一视口和交互路径验证。

## 界面类型

| 类型 | 首要目标 | 主要证据 | 常见错误 |
|---|---|---|---|
| 说服型 Persuade | 建立兴趣并促成行动 | 信息节奏、信任、CTA | 只追求视觉奇观 |
| 操作型 Operate | 快速准确完成任务 | 状态、密度、反馈、容错 | 把后台做成 Landing Page |
| 阅读型 Read | 清楚理解长内容 | 字宽、层级、导航、节奏 | 过度动效干扰阅读 |
| 体验型 Experience | 通过互动表达故事或品牌 | 连续性、场景、主动态 | 每个元素都抢注意力 |

混合页面必须声明主类型和次类型，不能平均分配设计重点。

## 方向选择

提出最多三个有实质差异的方向，并给出：适用理由、核心布局、字体角色、颜色比例、资产语言、signature moment、三个旋钮、实现成本和失败风险。明确推荐一个。方向一旦确认，把决策写入设计契约；禁止从其他方向抽取元素做折中拼盘。

## 实现门

进入大规模编码前确认：

- 真实内容或可信草稿已存在，不使用 Lorem Ipsum。
- 主要页面结构和用户路径已列出。
- 字体、颜色、间距和断点有明确规则。
- 所需媒体有来源、占位策略和替换计划。
- 动效与组件依赖已经过框架、许可和性能筛选。

## 评审隔离

大任务使用两条独立证据链：

1. 视觉/产品评审员只看 brief、设计契约和渲染产物，先不给静态扫描结论，避免锚定。
2. 实现验收员检查浏览器、响应式、状态、键盘、触控、控制台、构建和静态审计。

主代理最后合并两者，区分事实缺陷、审美判断和建议。不要让多个代理同时编辑同一文件。
