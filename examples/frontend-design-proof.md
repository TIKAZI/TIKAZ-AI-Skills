# Demonstration: frontend art-direction proof

This is a method demonstration, not a client case study.

## Brief

Redesign a dense operations dashboard without turning it into a marketing page. Operators must scan exceptions, compare severity, and act repeatedly on desktop and tablet.

## Design Read

- Surface: `Operate`
- Dominant task: detect and resolve exceptions
- Visual world: precision instrument panel, not a card gallery
- Dials: variance `3/10`, motion `2/10`, density `8/10`
- Anti-goals: oversized hero typography, decorative charts, repeated floating cards

## Proof contract

The representative proof must contain navigation, the exception queue, one selected detail state, desktop and mobile/tablet framing, and reduced-motion behavior. Full implementation is blocked until hierarchy, scan path, density, and action clarity pass screenshot review.

## Evidence expected

- `DESIGN.md` records the approved visual direction and invariants.
- Desktop and tablet screenshots are bound to the current revision.
- Build, responsive, keyboard, contrast, and reduced-motion checks are recorded in `QA.md`.

This example demonstrates the TIKAZ principle **proof before scale**: validate the visual system on the hardest representative slice before multiplying it across the product.
